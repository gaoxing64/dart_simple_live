# PR 说明：关注多分组归属 + 一键按平台智能分组

对应计划：[2026-10-12-multi-membership-and-smart-grouping-plan.md](2026-10-12-multi-membership-and-smart-grouping-plan.md)
实施偏离记录见该计划文末「附录：实施偏离记录」。

## 一句话

关注可以从「只能属于一个分组」变成「可以同时属于多个分组」，
并新增**一键把所有关注按平台自动分好组**（哔哩哔哩 / 斗鱼直播 / 虎牙直播 / 抖音直播 / Twitch）。

## 用户能感知到的变化

### 1. 一键按平台智能分组（本次的主要诉求）

两处入口，行为完全一致：

- **关注页顶栏 ⋮ 菜单** → 「按平台智能分组」（图标 `Remix.magic_line`）
- **关注设置页** → 「分组管理」卡片内的「按平台智能分组」

点下去先弹**确认弹窗**，把「将发生什么」摊开在执行之前：

| 分组 | 人数 | 状态 |
|---|---|---|
| 哔哩哔哩 | 12 | 新建 |
| 虎牙直播 | 8 | 复用（已有 8 位在内） |
| … | … | … |

- 平台名取 `Sites.allSites[id].name`（用户确认过）
- **所有**关注都会进它所属平台的分组（不是只归未分组的）——因为多归属下这个动作不破坏已有分组
- 已经在对应分组里的不算新增，`pendingCount = userCount - alreadyMemberCount`
- 分组顺序跟随「设置 → 站点排序」`siteSort`，`siteSort` 里没提到的平台按 `Sites.allSites` 顺序补在后面
- 真正被下架的平台会显示为「跳过 N 个未知平台」
- 无可归组内容时只 toast「所有关注都已在对应平台分组里」，不弹一张空表
- 幂等：重复执行不会重复加入，第二次会显示「没有需要归组的关注」

### 2. 一个关注可以同时属于多个分组

- **关注页**：一个主播出现在它的**每一个**所属分组卡片里（而不是只出现在主分组里）
- **关注详情页**：「所属分组」从单选下拉改成**多选 chips** —— 勾选=加入该分组，取消=移出该分组
- **快速分组 sheet**（卡面长按 → 移入分组）：可多选，文案改为「加入已有分组」/「移出所有分组」
- **拖拽分组**：把关注拖到分组卡上=加入该组；拖回本组不再被误判为「发生了移动」；
  拖到「未分组」区=移出所有分组
- **关注行副标题**：显示该主播的全部分组名（` · ` 连接、整体截 8 字），无归属显「全部」

### 3. 分组真源统一

归属的唯一真源改为 `FollowUserTag.userId`（成员表），
`FollowUser.tag` 原来兼职的「一个关注属于哪个分组」职责被彻底取消。

## 兼容性（**这部分必须在发布说明里写明**）

### 备份 / 导入

- **新版本导出的备份，旧版本仍能读**：导出 JSON 每条记录**同时**带
  `"tag"`（主分组，旧版本只认它）与 `"tags"`（多分组数组，新版本认它）。
  由 `follow_membership_test.dart` 的「备份向后兼容」用例钉住。
- **旧版本备份导入新版本**：读 `item['tags']`，没有就回退 `item['tag']`，行为不变。

### WebDAV 同步

按**分组名并集**合并（不是覆盖）：本地与远端都有的分组，成员取两侧 `userId` 的并集，
再按存活关注 id 过滤幽灵；分组 id 重新用 `FractionalIndexing` 排序生成。

### 老版本 app 读新数据（降级）

`FollowUser.tag`（HiveField 7）已删除，`hive_ce` 的 adapter 按 `numOfFields` 逐字段读：

- **不会崩**，旧记录里多出来的 field 7 被忽略。
- 旧版本 app 读到新记录时 `fields[7] == null` → 回退 `'全部'`，
  即**分组归属在旧版本看来丢失**。但成员表本身活在 `tagBox` 里、不受影响，
  重新升级到新版本后归属自动回来。
- **不要**在降级到旧版本后做「清理数据 / 重建分组」之类操作，那才会真的动到 `tagBox`。

### 升级到新版本

- 归属不会丢：`FollowUserTag.userId` 是长期真源（历史迁移 `curDBVer <= 10709`
  正是从它反推 `follow.tag`），旧库里的成员表本来就是对的。
- `migrateTagMembership`（v1.8.16 的一次性回填）在删除 `FollowUser.tag` 后已无源可读，
  按计划删除；它原本只是应对「`follow.tag` 与成员表不一致」的漂移兜底，
  而旧版 `setFollowTag` 一直同时维护两者，健康库里不会出现这种漂移。

## 手工验收清单（自动化覆盖不到的部分）

跑在真机/桌面上，重点是**数据**与**首次体验**：

- [ ] **升级不丢分组**：拿一份旧版本（v1.8.15）的用户库升级到本版本，
      打开关注页，每个关注仍在它原来的分组里、行副标题显示正确。
- [ ] **智能分组首次执行**：关注页 ⋮ → 按平台智能分组，确认弹窗里
      平台名与人数和实际关注数一致；确认后每个平台分组里都是该平台的主播。
- [ ] **智能分组重复执行**：再点一次，弹窗里各组都标「复用」、
      「待归组 0」，执行后 toast「没有需要归组的关注」，分组没有重复成员。
- [ ] **多归属**：给一个主播勾两个分组 → 关注页两张分组卡里都出现它 →
      取消一个分组 → 另一张卡里仍在。
- [ ] **拖拽**：拖到它**已经**在的分组 → 不高亮、不报错；拖到新分组 → 加入；
      拖到「未分组」→ 移出所有分组。
- [ ] **站点排序联动**：设置 → 站点排序，把顺序调乱，再跑一次智能分组的预览，
      分组顺序跟着 `siteSort` 走（已有分组不会被重复创建）。
- [ ] **换绑迁移**：关注详情页里换绑到另一个平台的房间，
      该主播原来所属的分组全部保留（不掉进「未分组」）。
- [ ] **备份往返**：导出 JSON → 清空 → 导入，多分组归属完整恢复；
      再拿这份 JSON 用**旧版本**导入，能看到主分组（不崩、不丢基础信息）。
- [ ] **WebDAV 合并**：两台设备各自把同一主播加进不同分组，同步后两台都变成
      「两个分组都包含它」（并集，不是互相覆盖）。
- [ ] **未进过关注页就用设置页入口**：冷启动 → 直接进关注设置 → 按平台智能分组，
      能正常弹窗并执行（这条对应计划「已知风险」第 1 条，已用测试钉住）。
